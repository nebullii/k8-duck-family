picture book guide

How the pond works

💻

1. Browser

The learner opens the duck page from a laptop.

🌉

2. Port-forward

A temporary bridge carries the browser request into Kubernetes.

🚪

3. Service

The Service is the stable front gate. It finds the right pod by label.

🏠

4. Pod

The pod is the duck house where one or more containers live.

🦆

5. Container

The container is the duck doing the work. For this page, nginx serves HTML.

📡

6. Sidecar

A second container, pond-watcher, asks Kubernetes how every pod is doing and writes a live report next to the page.

try it yourself

Run the same commands the page runs

See every pod's status (this is what the sidecar reads)

kubectl get pods -n duck-family

Look inside one family pod and its four containers

kubectl describe pod duck-daisy -n duck-family

Read the ConfigMap shown in the live panel above

kubectl get configmap duck-family-message -n duck-family -o yaml

Prove the dashboard is read-only (this should say "no")

kubectl auth can-i delete pods -n duck-family --as=system:serviceaccount:duck-family:duck-dashboard

Delete a family and watch its card go grey — these are bare pods, so it will not come back on its own (that is what Deployments are for). Re-apply to bring it home.

kubectl delete pod duck-daisy -n duck-family
kubectl apply -f k8s/pods/duck-daisy-pod.yaml
